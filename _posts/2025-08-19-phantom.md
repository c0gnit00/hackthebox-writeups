## 1. Executive Summary

Phantom is a hard Windows Active Directory machine running Windows Server 2022 in the `phantom.vl` domain. The attack chain demonstrates perimeter enumeration via anonymous SMB shares, user extraction via RID brute-forcing, password spraying default credentials, custom Hashcat rule generation for VeraCrypt container cracking, extracting VyOS router backup configurations for credentials, AppLocker / BloodHound Active Directory path analysis, ForceChangePassword ACL abuse, MachineAccountQuota (MAQ = 0) RBCD U2U impersonation, DCSync hash dumping, and Pass-the-Hash Evil-WinRM domain administrator compromise.

### Detailed Attack Chain Summary:

1. **Reconnaissance & Perimeter Scanning:** An all-port Nmap scan discovers open TCP ports including DNS (53), Kerberos (88), RPC (135), SMB (445), LDAP (389), LDAPS (636), WinRM (5985), and ADWS (9389).
2. **Anonymous SMB Enumeration & User Extraction:** Connecting to SMB anonymously exposes the `Public` share. Downloading `tech_support_email.eml` and an attached PDF discloses user `ibryant` and default onboarding password policy `Ph4nt0m@5t4rt!`. RID brute-forcing via `netexec smb --rid-brute` extracts domain usernames.
3. **Password Spraying & Authenticated SMB Access:** Password spraying `Ph4nt0m@5t4rt!` against the domain user list authenticates user `ibryant` (`ibryant` / `Ph4nt0m@5t4rt!`). SMB share enumeration with `ibryant`'s credentials grants access to `Departments Share`, where an IT backup file `IT_BACKUP_201123.hc` is located.
4. **Custom Hashcat Rules & VeraCrypt Container Cracking:** The `.hc` file is an encrypted VeraCrypt container. A custom Hashcat rule set (`phantom_rules.rule`) is generated based on password mutation patterns (`Phantom` -> `Ph4nt0m2023!`, etc.). Extracting the 512-byte header and running Hashcat mode 13722 (VeraCrypt) cracks the container password.
5. **VyOS Router Configuration & Credential Harvesting:** Mounting the VeraCrypt container discloses `vyos_backup.tar.gz`. Extracting `config.boot` reveals a plaintext SSTP VPN service account password for `svc_sspr` (`gB6XTcqVP5MlP7Rc`).
6. **WinRM Access & Initial Foothold:** Testing `svc_sspr` credentials against SMB and WinRM confirms administrative WinRM login permissions on `DC.phantom.vl`. Establishing an Evil-WinRM session lands initial access as `svc_sspr` and yields the user flag.
7. **BloodHound AD Path Analysis & ForceChangePassword Abuse:** Running `rusthound-ce` / `netexec ldap --bloodhound` maps domain ACLs. BloodHound discloses that `svc_sspr` holds `ForceChangePassword` control over user `wsilva`. Since `MachineAccountQuota` is 0 (preventing fake computer account creation for standard RBCD), `svc_sspr` resets `wsilva`'s password to `Password123!`.
8. **RBCD U2U Impersonation & DCSync Attack:** `wsilva` is used to configure Resource-Based Constrained Delegation (RBCD) directly targeting `DC$`. Using U2U (User-to-User) S4U2Proxy ticket requests via `getST.py -u2u` impersonates `Administrator`.
9. **Pass-the-Hash & Domain Compromise:** The forged Kerberos service ticket allows running `netexec smb -k --sam / --dcsync`, dumping the Domain Administrator NT hash (`aa2abd9db4f5984e657f834...`). Pass-the-Hash via Evil-WinRM connects as `Administrator` on `DC.phantom.vl` to capture the root flag.

## 8. Remediation & Security Recommendations

1. **Disable Anonymous SMB Access [High]:** Restrict null session and anonymous access to SMB shares (`Public`). Ensure sensitive onboarding documentation and emails are not accessible without domain authentication.

2. **Enforce Strong Password Policies [High]:** Eliminate predictable default password patterns (such as `Ph4nt0m@5t4rt!`) for new employee onboarding. Enforce immediate password reset on first login.

3. **Secure Hardened Container Encryption Passwords [Critical]:** Ensure encryption passphrases for administrative backups and containers (VeraCrypt `.hc` files) use long, complex, randomly generated passphrases that resist rule-based dictionary attacks.

4. **Sanitize Router Backup Files [Critical]:** Remove cleartext credentials from network appliance configuration files (`VyOS config.boot`). Secure backup archives using strong encryption and restricted file permissions.

5. **Restrict Active Directory Delegation ACLs [Critical]:** Audit and remove permissive `ForceChangePassword` rights granted to service accounts over user objects. Restrict `msDS-AllowedToActOnBehalfOfOtherIdentity` write permissions on computer objects to authorized Domain Admins.

6. **Monitor Kerberos S4U2Proxy & U2U Traffic [High]:** Enable auditing for Kerberos Ticket Granting Service (TGS) requests utilizing U2U and S4U2Proxy extensions for anomalous cross-user ticket requests.
