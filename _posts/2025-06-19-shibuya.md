## 1. Executive Summary

Shibuya is a hard Windows Active Directory domain controller running Windows Server 2022 in the `shibuya.vl` domain. The attack chain demonstrates perimeter scanning, domain user enumeration via kerberos / SMB authentication, extracting WIM system backup images from an unprivileged SMB share, extracting local offline SAM and SYSTEM hives to recover NTLM hashes, establishing SSH persistence as `simon.watson`, leveraging RemotePotato0 cross-session NTLMv2 relay to compromise `nigel.mills` (a member of Tier-1 Administrators), enumerating Active Directory Certificate Services (ADCS) for vulnerable templates, exploiting ADCS ESC1 misconfigurations (`ShibuyaWeb` template) to forge an Administrator certificate, and authenticating via Kerberos to achieve full domain compromise.

### Attack Chain Mechanics

The initial perimeter assessment begins by scanning TCP services on the target Domain Controller. Service enumeration reveals standard Active Directory protocols including DNS, Kerberos, RPC, SMB, LDAP, and WinRM. Enumerating domain users with `nxc smb` discloses the service account `svc_autojoin` with password `K5&A6Dw9d8jrK`.

Authenticating to SMB as `svc_autojoin` grants read access to the `images$` share, which contains Windows Imaging (WIM) backup files (`AWSJPWK0222-01.wim`, `AWSJPWK0222-02.wim`, `AWSJPWK0222-03.wim`). Downloading the WIM files and mounting them locally allows extracting the offline `SYSTEM`, `SAM`, and `SECURITY` registry hives. Executing `impacket-secretsdump` against the extracted hives dumps local SAM hashes, revealing the NTLM hash for user `simon.watson`.

Using `simon.watson`'s NTLM hash (`5d8c3d1a20bd63...`), authentication via `impacket-smbclient` allows uploading an SSH public key (`authorized_keys`) into `C:\Users\simon.watson\.ssh\`, establishing persistent SSH interactive access and establishing a SOCKS5 proxy tunnel.

Inspecting active sessions on the host reveals an active interactive session for `nigel.mills`. Leveraging `RemotePotato0` alongside a local `socat` listener redirects RPC authentication traffic to Kali, capturing the NTLMv2 response hash for `nigel.mills`. Cracking the NTLMv2 hash with John the Ripper using `rockyou.txt` yields the plaintext password `Sail2Boat3`.

Authenticating as `nigel.mills` via SSH reveals membership in `t1_admins` (`Tier-1 Administrators`). Enumerating Active Directory Certificate Services (ADCS) using `certipy-ad` via the SOCKS proxy identifies an ESC1 vulnerability in the `ShibuyaWeb` certificate template, which allows `ENROLLEE_SUPPLIES_SUBJECT` (SAN specification) for domain administrators.

`certipy-ad req` requests a forged certificate for `Administrator@shibuya.vl` using the `ShibuyaWeb` template. Authenticating with the resulting `.pfx` certificate via `certipy-ad auth` issues a Kerberos TGT and extracts the Administrator NTLM hash. Executing `impacket-psexec` and `impacket-secretsdump` with the Administrator hash grants full SYSTEM access on `AWSJPDC0522.shibuya.vl` and dumps the NTDS.dit domain database, capturing both user and root flags.

## 2. Reconnaissance

### 2.1 Full TCP Port Scan

Initial reconnaissance begins with a comprehensive all-port TCP SYN scan (`-sS`) across all 65,535 ports at a high packet rate (`--min-rate 5000`) with host liveness discovery disabled (`-Pn`) and max retries set to 1. Skipping host discovery ensures firewalls blocking ICMP echo requests do not obscure open services.

Execute the full TCP port sweep against target IP address `10.129.234.42`:

```bash
kali@kali:~$ nmap -sS -Pn --min-rate 5000 --max-retries 1 -T4 -p- 10.129.234.42
```

### 2.3 DNS Resolution & Hosts File Configuration

To enable native hostname resolution for Impacket, NetExec, Certipy, and SSH tools, the target FQDN and netbios name are appended to Kali's `/etc/hosts` file.

Configure host resolution mapping in `/etc/hosts`:

```bash
kali@kali:~$ echo "10.129.234.42 shibuya.vl AWSJPDC0522.shibuya.vl AWSJPDC0522" | sudo tee -a /etc/hosts
```

This configuration ensures all tools resolve `shibuya.vl` and `AWSJPDC0522.shibuya.vl` to `10.129.234.42`.

## 3. SMB Enumeration & Initial Credential Discovery

### 3.1 Domain User & Credential Enumeration

Initial SMB enumeration tests low-privilege or default credentials against the SMB service using `netexec`. User enumeration queries domain user lists from Active Directory.

Execute SMB user enumeration using `netexec`:

```bash

```

The command output confirms valid SMB domain connectivity and lists domain user accounts:



## 8. Remediation & Security Recommendations

1. **Active Directory Certificate Services Hardening [Critical]:** Secure vulnerable certificate templates (specifically `ShibuyaWeb`). Disable the `ENROLLEE_SUPPLIES_SUBJECT` flag (`CT_FLAG_ENROLLEE_SUPPLIES_SUBJECT`) on templates that allow authentication. Enforce manager approval for sensitive certificate issuance.

2. **Restrict Service Account SMB Share Access [High]:** Restrict SMB share permissions on `images$`. Ensure service accounts such as `svc_autojoin` do not have read access to system deployment images (`.wim` files) or backup directories containing offline registry hives.

3. **Secure Offline WIM & Backup Files [Critical]:** Ensure all backup images (`.wim`, `.vhd`, `.bak`) are encrypted using BitLocker or dedicated key management solutions. Sysprep and wipe local SAM and SYSTEM registry hives prior to packaging golden deployment images.

4. **Harden RPC & DCOM Authentication Protocols [High]:** Mitigate cross-session NTLM relay attacks (`RemotePotato0`) by disabling unauthenticated RPC/DCOM forwarding, enforcing SMB Signing across all endpoints, and implementing Extended Protection for Authentication (EPA).

5. **Privileged Account Password & Session Management [High]:** Implement strict session timeout rules for administrative users (`nigel.mills`). Enforce unique, complex passphrases for all Tier-1 and Tier-0 domain administrators to prevent password cracking via standard wordlists.
