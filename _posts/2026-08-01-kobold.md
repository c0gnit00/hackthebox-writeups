## Executive Summary

This report documents the full compromise of **Kobold**, a medium-rated Linux machine hosting multiple web services behind nginx reverse proxy. Initial access is achieved through a pre-authentication Remote Code Execution vulnerability in MCPJam Inspector. Privilege escalation chains a PrivateBin Local File Inclusion vulnerability with Docker container management to achieve root access.

### Attack Chain Summary:

1. **Reconnaissance & Service Discovery:** Nmap reveals SSH (22), HTTP/HTTPS (80/443), and a Golang HTTP service on port 3552 running Ubuntu 24.04. The SSL wildcard SAN `*.kobold.htb` indicates subdomains. Favicon fingerprinting identifies port 3552 as Arcane Docker management platform v1.13.0. Virtual host enumeration discovers `mcp.kobold.htb` (MCPJam Inspector v1.4.2) and `bin.kobold.htb` (PrivateBin 2.0.2).
2. **MCPJam Inspector Pre-Auth RCE (CVE-2026-23744 — `ben` on Kobold):** MCPJam Inspector v1.4.2 is vulnerable to CVE-2026-23744, a pre-authentication Remote Code Execution. The `/api/mcp/connect` endpoint accepts arbitrary `command` and `args` parameters without authentication, executing them directly on the host. A reverse shell payload via this endpoint yields shell access as `ben`.
3. **PrivateBin LFI to Docker Container Shell (CVE-2025-64714):** PrivateBin 2.0.2 is vulnerable to CVE-2025-64714, a Local File Inclusion via the template-switching cookie. The PrivateBin Docker container's data directory is bind-mounted from the host at `/privatebin-data/data/`, which is world-writable. Writing a PHP webshell to this directory and triggering the LFI via the `template` cookie achieves code execution inside the PrivateBin Docker container, leaking database credentials (`ComplexP@sswordAdmin1928`).
4. **Arcane Docker Container Escape to Root:** The leaked password authenticates to the Arcane Docker management interface as the default `arcane` admin user. With Docker admin access, a new privileged container is created mounting the host root filesystem (`/`) at `/hostfs`, granting full root access to the host.

### PrivateBin (bin.kobold.htb)

Visiting `https://bin.kobold.htb` reveals a PrivateBin 2.0.2 instance. PrivateBin is an open-source, zero-knowledge pastebin where content is encrypted client-side using AES-256-GCM before being sent to the server. The encryption key is embedded in the URL fragment (`#key`), which browsers never send to the server, ensuring the server only stores encrypted blobs.

<img src="assets/img/kobold/private_bin_url.png" alt="error loading image">

Opening the link in a separate browser prompts for the password, then decrypts and displays the paste:

<img src="assets/img/kobold/privatebin_decrypt.png" alt="error loading image">

Searching for vulnerabilities, [CVE-2025-64714](https://github.com/PrivateBin/PrivateBin/security/advisories/GHSA-g2j9-g8r5-rg82) affects PrivateBin's template-switching feature. When `templateselection` is enabled in the configuration, the server trusts the `template` cookie value and includes the referenced PHP file via path traversal, leading to unauthenticated Local File Inclusion (LFI). The template cookie value is used as a relative path from the `tpl` folder, allowing inclusion of arbitrary PHP files on the filesystem. Template selection is enabled on this instance, with the current theme reflected in the cookie value:

## Initial Foothold — MCPJam RCE (CVE-2026-23744)

[CVE-2026-23744](https://github.com/advisories/GHSA-232v-j27c-5pp6) is a pre-authentication Remote Code Execution vulnerability in MCPJam Inspector versions 1.4.2 and earlier. The `/api/mcp/connect` API endpoint, designed for connecting to MCP servers, accepts `command` and `args` fields without performing any authentication or input validation. When an HTTP request reaches the `/connect` route, the system extracts and executes these fields as arbitrary OS commands. Unlike CVE-2025-49596 which requires user interaction, this vulnerability is exploitable remotely via a single HTTP request with no user interaction.

> **Misconfiguration:** MCPJam Inspector is a developer debugging tool intended for local development use. Exposing it on a production server via a public-facing nginx reverse proxy without authentication creates a direct RCE entry point. Development tools should never be deployed on production systems or should be restricted to localhost-only access behind VPN.

The vulnerability can be exploited via the GUI by clicking `Add Server` and entering the desired command, but I will prefer CLI:

<img src="assets/img/kobold/mal_server.png" alt="error loading image">

Since the `/api/mcp/connect` endpoint executes commands but does not return their output, an out-of-band data exfiltration technique is needed. Start a custom HTTP server to receive base64-encoded command output:

```shell
#!/usr/bin/env python3

# python3 server.py
from http.server import BaseHTTPRequestHandler, HTTPServer
import base64
import urllib.parse

PORT = 8888

class Handler(BaseHTTPRequestHandler):
    def do_POST(self):
        content_length = int(self.headers.get('Content-Length', 0))
        body = self.rfile.read(content_length)

        # Try to extract base64 from form data (data=...) or use raw body
        try:
            parsed = urllib.parse.parse_qs(body.decode())
            b64_data = parsed.get('data', [None])[0]
        except Exception:
            b64_data = body.decode().strip()

        if b64_data:
            try:
                decoded = base64.b64decode(b64_data).decode('utf-8', errors='replace')
                print("\n--- DECODED DATA ---\n")
                print(decoded)
                print("\n--- END ---\n")

                self.send_response(200)
                self.end_headers()
                self.wfile.write(b"OK: received and decoded\n")
            except Exception as e:
                self.send_response(400)
                self.end_headers()
                self.wfile.write(f"Decode error: {e}".encode())
        else:
            self.send_response(400)
            self.end_headers()
            self.wfile.write(b"Missing data\n")

    def log_message(self, format, *args):
        # Suppress default request logs; uncomment below to see them
        # super().log_message(format, *args)
        pass

if __name__ == "__main__":
    server = HTTPServer(("0.0.0.0", PORT), Handler)
    print(f"[*] Listening on 0.0.0.0:{PORT}")
    server.serve_forever()
```

## Unintended Path — Docker Group via newgrp

While running LinPEAS, an alternative privilege escalation path was discovered. The `ben` user can join the `docker` group via `newgrp`, even though `id` doesn't show membership:


This discrepancy occurs because `ben` was removed from the `docker` group by directly editing `/etc/group` instead of using the proper command (`sudo gpasswd -d ben docker`). The `/etc/group` file does not list `ben` under the `docker` group, but `/etc/gshadow` still grants membership:

```shell

root@kobold:~# cat /etc/gshadow | grep docker
```

> **Misconfiguration:** Group membership in `/etc/gshadow` is inconsistent with `/etc/group`. When removing users from groups, always use `gpasswd -d` or `deluser` rather than manually editing `/etc/group`, as these commands update both files atomically. The `newgrp` command checks `/etc/gshadow` for membership, bypassing the apparent group removal.

## Remediation & Security Recommendations

**CVE-2026-23744 — MCPJam Inspector Pre-Auth RCE [Critical]:** Upgrade MCPJam Inspector to a version newer than 1.4.2. The `/api/mcp/connect` endpoint must validate authentication before accepting connection requests and should sanitize the `command` and `args` fields against a strict allowlist of permitted MCP server binaries. Developer debugging tools like MCPJam Inspector should never be deployed on production systems.

**CVE-2025-64714 — PrivateBin Template LFI [High]:** Upgrade PrivateBin to a patched version. If template selection is not needed, disable it in the configuration. The `template` cookie value should be validated against a strict allowlist of permitted template names and should reject any path traversal characters.

**World-Writable Docker Bind Mount [High]:** The `/privatebin-data/data/` directory is bind-mounted into the Docker container with `777` permissions, allowing any host user with `operator` group membership to write arbitrary files into the container's filesystem. Combined with the LFI vulnerability, this grants code execution inside the container. Restrict the bind mount permissions to `770 root:www-data` and ensure only the container's web process can write to the data directory.

**Password Reuse Between Services [Medium]:** The same password `ComplexP@sswordAdmin1928` is used for both the PrivateBin MySQL database and the Arcane Docker management admin account. Use unique, randomly generated passwords for each service, managed via a secrets manager.

**Docker Management Interface Exposure [Critical]:** The Arcane Docker management interface grants full container lifecycle control including the ability to create privileged containers with host filesystem mounts. This is equivalent to root access on the host. Docker management interfaces should be restricted to trusted administrators via network ACLs, require MFA, and should audit all container creation events. Consider using Docker's `--userns-remap` to prevent trivial container escapes via UID 0 mounts.

**Inconsistent Group Membership (`/etc/group` vs `/etc/gshadow`) [Medium]:** The `ben` user was removed from the `docker` group in `/etc/group` but remained in `/etc/gshadow`, allowing re-entry via `newgrp`. Always use `gpasswd -d` or `deluser` to remove group memberships, as these commands update both files. Periodically audit group membership consistency with `grpck`.
